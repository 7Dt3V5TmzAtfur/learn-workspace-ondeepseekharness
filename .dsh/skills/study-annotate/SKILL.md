# 读中标注（study-annotate）

## 核心机制：注意力预算

**不是每段都标。** 三色不是装饰，是注意力分配：
- 蓝色（核心，`#d`/`#s`）：必须能合书复述的骨架 —— 定义、结论。**≤ 全文 10%**
- 红色（攻坚，`#q`/`#v`）：必须停下来想的 —— 疑问、难点、验证点。**≤ 全文 8%**
- 绿色（参考，`#e`/`#t`/`#c`）：例子、迁移、备注 —— 需要时回查，不参与精读

总高亮 **≤ 20%**。`study_save` 会硬性拒绝超预算的提交。
被拒时**降级**：把边缘段落从核心降到参考，或干脆不标 —— 绝不要为了过校验去改数字。

## 七类标签的判定

来源：`tools/渐构+文案拆解标注.md`。输出格式固定为一行标签 + 一段原文：

```
#d 什么是注意力预算|Definition
注意力预算指…

#e 复习场景的类比|Example
就像…
```

| 标签 | 什么时候用 | 反例（别这么用） |
|---|---|---|
| `#d` 定义 | 明确给出"X 是 Y"、界定范围、说明机制 | 一段叙述里夹了半句解释不算 |
| `#e` 例子 | 具体案例、数据、演示、类比 | 抽象复述不算例子 |
| `#q` 提问 | 作者提出待解决问题、或你觉得这里说不通 | 修辞性设问不算 |
| `#s` 总结 | 结论、归纳、"因此" | 段落收尾的过渡句不算 |
| `#t` 迁移 | 推广到新领域、给出行动建议、启发式 | 例子后的一句感慨不算 |
| `#c` 备注 | 以上都不合适时的补充说明（比喻、背景、术语对照） | **必须带两个字的类目关键词**，如 `#c 背景 …`、`#c 术语 …` |
| `#v` 验证 | 实验、测试、证明、"这可以通过…检验" | 空口断言不算 |

**一段只给一个标签**，选最主要的角色。含糊的地方优先用 `#c` 加关键词。

## 流程

1. `study_read { docId, offset, limit: 20 }` 分批取段落，记住每段的 `¶N` 锚点与字数。
2. 边读边判断角色，先只做**筛选**：这段值得精读吗？值得 → 给档位；不值得 → 不标。
3. 全部读完再统一提交（避免前后预算失衡）：
   ```
   study_save { docId, kind: 'annotation', payload: { items: [
     { segmentId: '¶3', label: 'd', title: '注意力预算的定义', note: '…' },
     { segmentId: '¶7', label: 'q', title: '为什么上限是 20%', note: '…' }
   ] } }
   ```
   `tier` 可省略，系统按标签自动归档；只有确需跨档时才显式写。
4. 看返回的 `check.issues` 与 `check.stats`，按上面说的方式**降级**修正。

## 每段还要给什么

- `title`：标签后的高度概括短语，**不超过 20 字**，写"这段说了什么"，不写"这是个定义"。
- `note`：可选。写"我读到这里的反应"：疑问、联想、要回头查的点。

## 配套交付：问答对与最小行动

标注完成后，在回答里追加（也可让用户单独要）：

**问答对**（复述用，每问每答都 ≤100 字）：
```
Q：注意力预算限制的是哪三档？
A：蓝色核心≤10%、红色攻坚≤8%、总高亮≤20%，超了就必须降级。
```

**最小 MVP 行动**：一句"明天 10 分钟内能做完"的具体动作。
例：「用蓝笔在打印稿上把 3 处 `#d` 抄成一张卡片，明早不看原文复述一遍。」

## 常见失败模式

- **全段都标蓝** → 预算爆掉，且等于没标。蓝色只给"忘了它就等于没读"的段。
- **`#c` 不带关键词** → 校验直接报错。写成 `#c 类比 …` 而不是 `#c …`。
- **按换行机械切段** → 语义被切碎。若发现某段其实是两个角色，用 `note` 说明，或把主要角色标在整段上。
- **只标不解释** → 用户看不懂为什么标。`title` 必须是一句人话。
