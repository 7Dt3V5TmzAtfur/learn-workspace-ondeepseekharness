# 读中标注（study-annotate）

## 你要产出什么

每条标注 = ①这段的角色标签 + ②原文章里的一句 **quote** + ③为什么标它。

`quote` 是这套机制的核心，不是可选项：

- 它是**原文里逐字存在的短语**，不是你的概括
- 系统会把它在原文的对应位置加粗上色
- 找不到就整个提交被拒（错误码 `quote-not-found`）

## 为什么必须是短语而不是整段

用户要的是「用三种颜色加粗原文」，目的是**通读时眼睛自动跳到关键短语**。

如果整段变色，每段都是一整块色块，人眼无法判断"这句里哪个词最关键"，三色就退化成一个贴纸，注意力机制失效。

而且预算按高亮字数算：标整段 200 字就花掉 200 字预算，一两个段落就把额度用光；标一句 20 字只花 20 字。

**所以：一段里挑一句最关键的，长度建议 8–30 字，不超过该段的 60%。**

## 三色档位

| 档位 | 标签 | 含义 | 预算 |
|---|---|---|---|
| 核心（蓝） | `#d` `#s` | 忘了它就等于没读：定义、结论 | ≤ 全文 10% |
| 攻坚（红） | `#q` `#v` | 必须停下来想：难点、疑问、验证点 | ≤ 全文 8% |
| 参考（绿） | `#e` `#t` `#c` | 需要时回查：例子、迁移、补充 | 不限，不计入预算 |

总高亮 ≤ 20%。超了 `study_save` 会硬拒。**被拒要降级或缩短 quote，绝不要改数字蒙过去。**

## 七类标签怎么判

来源：`tools/渐构+文案拆解标注.md`。

| 标签 | 什么时候用 | 反例 |
|---|---|---|
| `#d` 定义 | "X 是 Y"、界定范围、说明机制 | 叙述里夹半句解释不算 |
| `#e` 例子 | 具体案例、数据、演示、类比 | 抽象复述不算 |
| `#q` 提问 | 作者提出待解决问题，或你觉得说不通 | 修辞性设问不算 |
| `#s` 总结 | 结论、归纳、"因此" | 段落收尾的过渡句不算 |
| `#t` 迁移 | 推广到新领域、给行动建议 | 例子后的一句感慨不算 |
| `#c` 备注 | 以上都不合适（比喻、背景、术语对照） | **必须带两个字的类目关键词** |
| `#v` 验证 | 实验、测试、证明、"可通过…检验" | 空口断言不算 |

一段只给一个标签，选最主要的角色。

## 流程

1. `study_read { docId, offset, limit: 20 }` 分批取段落，记下 `¶N` 锚点、字数、正文。
2. 边读边判断：这段值得精读吗？不值得就不标（**不标是正常且正确的选择**）。
3. 值得标的，**从这段正文里原文挑一句**做 quote —— 复制原文，不要改字。
4. 全部读完再统一提交（避免前后预算失衡）：

```
study_save { docId, kind: 'annotation', payload: { items: [
  { segmentId: '¶15', label: 'd', tier: 'core',
    quote: '工具设计的早期形态是直接的 API 封装',
    title: '早期形态：API 封装',
    note: '这是后面讲形态谱系的起点' },
  { segmentId: '¶61', label: 'q', tier: 'hard',
    quote: '一次让模型看见多少条能力',
    title: '披露量的核心问题' }
] } }
```

5. 看返回的 `check.issues`：
   - `quote-not-found` → 你引的原文不对，回原文重挑（最常发生在表格、跨行句子上）
   - `quote-too-long` → quote 占了整段 90% 以上，缩短
   - `budget-*` → 降档或缩短 quote
   - `no-quote` → 忘了给 quote

## 三个必须提前知道的约束

这三条都是校验器会直接拒的，不是建议：

| 约束 | 错误码 | 说明 |
|---|---|---|
| **一段只能一条标注** | `duplicate` | 同一 `segmentId` 出现两次就报错。想同时标定义和例子，只能选一个当 `label`，另一个写进 `note` |
| **`#c` 必须带两字关键词** | `c-needs-keyword` | 格式是 `#c 对比 概括内容\|English`。三字会触发 `c-keyword-len` 警告 |
| **纯标题段和正文段是两个段** | `quote-not-found` | `## 执行工具`、`**安全机制的层次化设计。**` 这类只有标题的段落，正文在下一段。把正文的 quote 挂到标题段上必然失败 |

还有一条隐蔽的：**`quote` 不能跨 `**` 加粗标记**。
原文 `**感知工具**是 Agent 主动获取信息的方式`，如果你 quote 写
`感知工具是 Agent 主动获取信息的方式`，逐字匹配会失败，因为原文中间有 `**`。
取 `**` 之后的半句，或整段跳过加粗部分。

## 读的时候顺手做一次"暂停回顾"

界面在读中面板会把**核心档（`tier: 'core'`）段落先盖住**，让用户先写一句
自己的理解再对照原文 —— 依据 `原则/C1.02.a_高效学习策略/暂停回顾策略`：
阅读的核心动作不是读，而是停。

这对标注的影响：

- 你标成 `core` 的段落，用户读到时会被要求停下回想。**所以 `core` 要克制**，
  只给真正"必须能复述"的骨架。标太多会让阅读变成不停被打断。
- `hard`（提问/验证类）不会被盖住 —— 这类段落本身就是在抛问题，
  盖住反而看不出在问什么。
- `ref`（例子/迁移/备注）也不会被盖住，它们是随时可回查的素材。

判断标准：**这段如果用户记不住，后面的内容就跟不上了 → `core`；
只是有意思或有用的 → `ref`。**

## 挑 quote 的判断标准

**好 quote**：单独拿出来也说得清一件事，且是这段的骨架。

- ✓ `一次让模型看见多少条能力`
- ✓ `默认取向是通用优于专用`
- ✗ `按需`（脱离了原文没意义）
- ✗ `部署应用`（只是词，不是判断）
- ✗ 整段照抄（等于没挑）

**给表格挑 quote** 时，挑表头或某一行完整的一句，别跨行。

## 还要给什么

- `title`：不超过 20 字，写"这段说了什么"，不写"这是个定义"。
- `note`：可选，写你读到这里的反应：疑问、联想、要回头查的点。

## 常见失败模式

- **全标蓝** → 预算爆掉，等于没标。蓝色只给"忘了它就等于没读"的段。
- **quote 抄整段** → 校验警告 + 预算爆表。挑一句。
- **quote 自己概括** → 必然 `quote-not-found`。必须复制原文。
- **为了过校验删标注** → 别删，降档（core → ref）就行。
- **每段都标** → 182 段里标 37 段是合理的；标 150 段说明没在做筛选。
