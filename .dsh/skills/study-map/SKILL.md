# 知识图谱（study-map）

## 为什么需要这张图

单点知识靠记忆，**关系**靠理解。读完之后脑子里如果只有一堆散点，等于没学会。
这张图要回答三个问题：
1. 哪个知识点是**地基**（别人都依赖它）？
2. 哪两个容易**混**（对比关系）？
3. 我的**学习顺序**应该是什么（前置链的拓扑序）？

## 关系定式（八选一，别自创）

参照 `思维地图八大可视化模组`：

| relation | 含义 | 图解形状 | 例句 |
|---|---|---|---|
| `prerequisite` | A 是理解 B 的前提 | 流程箭头 | 「方差」是「标准差」的前置 |
| `part-of` | A 属于 B | 括号图/树 | 「中位数」属于「集中趋势度量」 |
| `contrast` | A 与 B 相互区分、易混 | 双气泡图 | 「精确率」对比「召回率」 |
| `cause` | A 导致 B | 复流程图 | 「样本偏差」导致「结论失效」 |
| `example-of` | A 是 B 的例子 | 桥形图 | 「抛硬币」是「伯努利试验」的例子 |
| `application` | A 用于 B | 箭头+场景 | 「大数定律」用于「保险定价」 |
| `sequence` | A 先于 B（纯先后） | 顺序链 | 「先归一化」先于「再降维」 |
| `analogy` | A 与 B 同构 | 桥形/并置 | 「信息熵」类比「热力学熵」 |

## 流程

1. 从 `preflight.json` 的 `knowledgePoints` 拿候选，从 `annotations.json` 的 `#d`/`#s` 段补漏。
2. 节点要**可数**：15–40 个。超过 40 就说明切得太碎，合并同义项。
3. 每个节点给 `id`（短英文或拼音，如 `k1`、`variance`）、`label`（中文名）、`kind`（`definition` / `principle` / `method` / `example` / `metric`）。
4. 连边。每个节点**至少一条边**（孤立节点说明你还没想清它和谁有关）。
5. 提交：
   ```
   study_save { docId, kind: 'relations', payload: { direction: 'TD', nodes: [...], edges: [...] } }
   ```
6. 看返回：
   - `check.issues` 有 `cycle` → 前置关系成环，说明你的理解有问题，**必须**重新想依赖方向，别绕过校验。
   - `isolated` 警告 → 补边或删节点。
   - `mermaid` → 直接可用。

## 出图：交给 archify

拿到 `mermaid` 后，如果用户要"能看的图"，加载 `archify` 技能：

```
加载 archify 技能，输入：
- 类型：architecture（或 tree，取决于图形态）
- 数据源：上面返回的 mermaid
- 标题：<资料标题> 知识点逻辑衔接图
```

archify 会产出独立 HTML，带交互与明暗主题。产物路径告诉用户，别只说"已生成"。

如果 archify 不可用，退而求其次：
- 直接给 Mermaid 代码块（多数编辑器能渲染）
- 再给一份**纯文本拓扑序**：「建议学习顺序：k1 → k3 → k2 → …」

## 拓扑序怎么算

对 `prerequisite` 子图做拓扑排序，就是学习顺序。
同一层内按 `contrast` 成对放，方便对比学习。
如果有环（理论上不该有），在回答里明确指出"这三条依赖构成循环，说明概念理解有矛盾"，并列出环路径。

## 回答里必须给出

1. 一句话概括这张图的形状（"一棵以 X 为根的树" / "两个中心 + 若干卫星" / "一条链"）。
2. **地基节点**：入度为 0 的那几个 —— 这是先学的。
3. **枢纽节点**：出度最高 —— 这是通吃的关键，值得多花时间。
4. **易混对**：所有 `contrast` 边，建议做成对比表。
5. 学习顺序（拓扑序）。

## 常见失败

- **把章节目录当知识点** → 那不是知识点，是标题。知识点要能被考。
- **所有关系都用 prerequisite** → 八种定式白设计了。对比就用 `contrast`，例证就用 `example-of`。
- **节点太细**（一句话一个节点）→ 图不可读。合并到"一个能单独考的概念"粒度。
- **不校验就交付** → 环没被发现，学习顺序是错的，用户按它学要返工。
