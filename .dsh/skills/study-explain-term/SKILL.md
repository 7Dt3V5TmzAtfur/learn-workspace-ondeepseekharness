# 术语追问（study-explain-term）

## 一句话原则

**给"在这句话里的意思"，不给"字典里的意思"。**

同一个词在不同学科里完全不同：`field` 在物理是场、在数据库是字段、在数学是域。
脱离语境解释等于没解释。

## 回答结构（固定五段，简短）

```
【在这句话里】一句话直译成大白话，把术语替换掉。
【为什么这么说】这个词的构词/来源，或它在本文的用法与常见用法的差别。
【打个比方】一个生活化的类比（必须贴切，不要凑）。
【往上接】它和上文哪个概念是一伙的 / 依赖什么前提。
【还可能在别处指】1–2 个别处含义，防止以后串味。
```

总长控制在 150–250 字。用户是在阅读中途被打断的，不是来上课的。

## 必须做的事

1. **先取上下文**。如果不知道段落，用 `study_read` 找到它，或者问用户"是第几段"。
2. **落库**：
   ```
   study_term { docId, term: '基频', segmentId: '¶12',
                question: '用户原话', answer: '你写的五段解释' }
   ```
   这样复习时能看到"我当时在哪卡住过"。
3. **区分三种情况**，明确告诉用户是哪一种：
   - 这个词在本文有**特定定义** → 指回定义段（`¶N`）
   - 这个词是**通用概念**，作者默认读者已知 → 补基础
   - 这个词**本文用得不严谨**或与通行用法冲突 → 指出来，这是高价值发现

## 语音提问

用户可能是语音输入的，识别结果常有同音错字（"基频"→"机频"）。
如果原词查不到或明显不通，**先猜最可能的原词**，说"你大概是想问 X？"，然后照答。
不要因为错字就要求用户重说。

## 不要做的事

- 不要给一整段百科式定义再补一句"在本文中……"。**顺序反了**：先说本文，再补通用。
- 不要编词源。不确定就写"来源不确定，但在这里指……"。
- 不要把回答写成 500 字。用户会跳过。
- 不要只答这个词，还要说它**在你现在读的这一段的论证里起什么作用**（承上/转折/限定）。

## 追问升级

如果用户连续追问同一个概念三次以上，说明这是个**知识缺口**，不是词义问题。
这时主动提议：「这不是一个词的问题，建议把 ¶N–¶M 三段的 `#d` 抽出来做成一张概念卡，
我可以顺手补进读前建构的难点列表。要吗？」
