# 读后巩固（study-recall）

## 这一步解决什么

读完 182 段以后，你在三天内会忘掉大部分。对抗遗忘最有效的不是重读，而是**主动回忆**：
合上原文，先自己答一遍，再核对。

这一步产出两样东西：

1. **QA 自测清单**（每条问题和回答各 ≤100 字）
2. **一个最小 MVP 行动**（"明天 10 分钟内能做完"的具体动作）

## QA 怎么写才算好

**问题要指向可检验的要点，不要问"这段讲了什么"。**

| 差 | 好 |
|---|---|
| 第五部分讲了什么？ | 工具太多会带来哪三重代价？ |
| 讲一下披露策略 | 层次化索引为什么比一次性全列出来更省 token？ |
| 什么是 ACI？ | ACI 要求工具对应什么，而不是对应什么？ |

**回答要在 100 字内闭环**，不要"详见上文"。

每个问题可以带上 `segmentIds`（如 `['¶61','¶62']`），界面就能回跳到原文核对。

## 流程

1. 确认标注已完成：`study_status { docId }` 看 `progress.annotated`。
   如果还没标注，先做 `study-annotate` —— 没标注就没有要点可问。
2. 按**部分**组织问题，每个部分 2–4 条，总数 6–12 条。
   太多会让人不想做；太少覆盖不到。
3. 提交：

```
study_save { docId, kind: 'qa', payload: { pairs: [
  { q: '工具爆炸带来哪三重代价？',
    a: '准确率随工具数下降、工具定义占满上下文、频繁变更击穿 KV Cache。',
    segmentIds: ['¶61'] },
  { q: '五类工具里哪一类是 Agent 主动调用的？',
    a: '感知、执行、协作都是主动调用；事件触发是被动的；用户沟通也由 Agent 主动发起。',
    segmentIds: ['¶8'] }
] } }
```

校验会拒掉超过 100 字的问题或回答。**超了就删字，不要截断**——截断会把意思弄丢。

4. 讨论最小 MVP 行动。参考"原则"目录里的《主动思考型信息训练》，行动要满足：
   - 明天 10 分钟内能做完
   - 有可观察的产出（一张卡片、一段复述、一次改写）
   - 直接用到刚学的东西

   例：「用 3 分钟把五类工具画成一张五行表，每类写一句'什么时候用它'，明早不看原文补一遍。」

## 不要做的事

- **不要在 QA 里复述原文** → 那是抄书。回答要换成自己的话。
- **不要出成考试卷** → 20 道题没人会做。6–12 条足够。
- **不要跳过最小行动** → 只记住不做事，一周后就回到原点。
- **不要替用户回答** → QA 是给用户自查的，答案默认收起，让用户先想。

## 下一步

QA 完成后进入 `study-feynman` 做真正的考核（让用户用自己的话讲一遍并判卷）。

## QA 只是开始：间隔复习怎么排

生成 QA 不等于记住了。自测通过与否，交给 `study-feynman` 的三道门槛判定；
**判定通过之后，系统才会把这份资料排进复习队列，间隔 1 → 3 → 7 天。**

- `study_review { action: 'list' }` —— 今天该复习哪些（`due` / `upcoming` 两组）
- `study_review { action: 'complete', docId }` —— 复习完一次，间隔推进到下一档

三条纪律：

- **不要替用户提前复习**。间隔没到就重看，间隔效应白费。
- **不要重出 QA**。复习是拿已有 QA 做主动回忆，不是再生成一批新的。
- 复习完一轮（7 天后）再问用户要不要重做费曼复述，那时才是下一个循环。

界面读后自测页会显示「加工进度 N/M 段、还剩几段没标」，可以展开看具体是哪几节。
**只提示，不阻断** —— 但用户看到还剩一大截时，通常会想回去补。
