# 读前建构（study-preflight）

## 核心立场

**先答"这对我有什么用"，再谈"这讲了什么"。**
学习主体是人，资料是注解。所以六段式里，摘要只占第 1 段，第 2–6 段全部是"我怎么用它"。

## 动手前

```
study_status                                   # 确认已导入、拿到 docId
study_read { docId, offset: 0, limit: 30 }      # 先看开头
study_read { docId, offset: 30, limit: 30 }     # 长文档继续，直到看见结尾
```

必须**真的读完全文**再写。禁止只看前几段就编造后面部分的重难点。

## 六段式产出结构

用 `study_save { docId, kind: 'preflight', payload: {...} }` 提交：

```json
{
  "summary": "…约 300 字…",
  "goals": {
    "help": "第一，…；第二，…",
    "main": "读完这份资料我要能做到的一句话能力",
    "subgoals": [
      { "text": "…", "level": "理解" },
      { "text": "…", "level": "掌握" }
    ]
  },
  "parts": [
    {
      "title": "第一部分标题",
      "requirements": "这部分要求我做到什么",
      "keyPoints": ["重点 1", "重点 2"],
      "difficulties": ["难点 1：为什么难"],
      "assessment": {
        "level": "掌握",
        "purpose": "我为什么要达到这个程度",
        "requirement": "达标的具体表现（可观察、可验证）"
      },
      "knowledgePoints": [
        { "name": "知识点名", "content": "内容要点", "note": "备注：易错点/联系/记忆钩子" }
      ]
    }
  ],
  "exercises": [
    { "question": "…", "kind": "回想|解释|应用|迁移|批判", "rubric": ["达标要点"], "hint": "…", "minimalAction": "明天能做的具体一步" }
  ],
  "references": [
    { "title": "…", "author": "…", "kind": "原文|我的知识|联网检索", "url": "…", "note": "用来补什么" }
  ]
}
```

## 各段写法要求

### ① 摘要（目标 300 字）
写"这份材料自己说了什么"，不写你的评价。作者要解决的问题 → 用了什么办法 → 得到什么结论 → 前提假设是什么。
不出现"本文""作者认为"这类空话，直接说事。300 字左右，允许 ±40%。

### ② 对我的帮助与目标
- `help` 必须写**两条**，且必须具体到"能解决我哪个具体问题"，不能写"提升认知"。
- `main` 是总目标，一句话，动词开头（能解释／能判断／能动手做）。
- `subgoals` 3–6 条，每条挂一个 `level`。子目标合起来要能撑起总目标。

### ③ 重点与难点
- **重点**是"就算别的都忘了也必须留下"的东西，通常来自作者的结论和关键定义。
- **难点**要写**为什么难**：符号陌生？前提没交代？跨领域？反直觉？抽象度高？
  "难点：本章较难"是废话，不合格。

### ④ 考核方式与知识点
- `level` 只能取四档之一，且必须与 `requirement` 匹配：

  | 档位 | 达标表现（用这些动词） |
  |---|---|
  | 了解 | 知道、说出、列举、认出、描述 |
  | 理解 | 解释、说明、举例、归纳、推断、比较 |
  | 掌握 | 应用、使用、解决、操作、计算、分析 |
  | 熟练掌握 | 综合、迁移、重构、设计、优化、教给别人 |

  写"掌握"却只要求"能说出定义"，就是不匹配 —— 校验会警告。
- **每个知识点**必须有 `content`（是什么）和 `note`（备注）。备注写三类之一：
  ① 易错/易混点；② 与前面哪个知识点相连；③ 记忆钩子（比喻、口诀、画面）。
  备注空着的知识点等于没加工，校验会报警告。

### ⑤ 思考题与作业（费曼）
每题标 `kind`，五类都要有覆盖，至少 5 题：
- **回想**：合上书，说出 X 的三个要素。
- **解释**：向一个外行讲清 X，不许用术语 Y。
- **应用**：给一个新情境，用 X 算出/判断出什么。
- **迁移**：X 的逻辑还能用在什么别的地方？
- **批判**：X 在什么条件下失效？作者哪里跳过了论证？

每题给 `rubric`（2–4 条达标要点，用来自己判卷）和 `minimalAction`（**明天 10 分钟内能做完**的一步）。

### ⑥ 参考资料
至少 3 条，必须诚实标注 `kind`：
- `原文` —— 资料自身的前言/附录/引用文献
- `我的知识` —— 我知道的经典教材/标准，要能给准确书名或标准号
- `联网检索` —— 只有**真的搜过**才能写，并给出 URL

宁可少写也不要编。编一条假文献，用户按图索骥找不到，整套系统的信任就没了。

## 提交后

`study_save` 会返回 `check.issues`。有 `error` 就修完再提交；`warn` 要判断：
- `summary-length` → 调整字数
- `part-purpose` → 补"我的目的是什么"
- `kp-note` → 补备注（不要留空）

然后告诉用户：「读前建构已完成，包含 N 部分 / M 个知识点 / K 道思考题。建议先看第 3 部分的难点，那里需要停久一点。现在可以开始精读标注了吗？」

## 降级路径

没有插件工具时，把同样的六段式直接输出成 Markdown，标题用 `## ① 资料摘要` 这样的编号，结构字段照样齐全，并明确说明"未落盘，只是临时会话产出"。
