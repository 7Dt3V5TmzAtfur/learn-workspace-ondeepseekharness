# TICKET: 考核环节只校验"答案非空"——一句话就能骗过整条链

- **状态**: open
- **类型**: `grilling`（HITL — 涉及要不要把门槛定死）
- **阻塞**: 无
- **所属**: [MAP](../../map/MAP.md)

## Question

`service.js` `recordDrill` 是整条流程里**唯一无法伪造的推进点**（`quiz.md` 在读前就生成，所以只有 `drills.jsonl` 的真实记录才能点亮"考核"）。

但它只做了一件事：

```js
async recordDrill(docId, { prompt, answer, rubricHit, verdict, minimalAction } = {}) {
  const text = String(answer ?? '').trim()
  if (!text) throw new Error('缺少你的复述/作答内容：请先真的用自己的话说一遍')
  const record = { at, prompt, answer: text.slice(0, 4000), rubricHit, verdict, minimalAction }
  // …appendJsonl('drills.jsonl', record)
}
```

**任何一句"我学完了"都能把阶段推到 `drilled`。**

这同时让三条学习规律失效：

| 规律 | 出处原文 | 现状 |
|---|---|---|
| 一分钟复述 | 「1 分钟内…"这本书解决了 XX 问题，提供了 XX 方法，案例证明了 XX 效果"」 | `drills.jsonl` 没有时长字段 |
| 主动提取优于被动复读 | 「合上书…榨干记忆后方可翻书补充」 | 没有闭卷状态字段 |
| RIA 不照抄 | 「用自己的语言重述…不照抄原文」 | `answer` 与原文零比对 |

## 三个维度的取舍

**维度一：用户的注意力机制**
如果考核可以一句话过，用户就会一句话过——不是他懒，是系统允许。门禁存在的意义是**在他想偷懒的那一刻挡住他**。但门槛太高会让人放弃（放弃比敷衍更糟）。

**维度二：数据结构**
需要新增哪些字段才能支撑校验？
- `durationSec`：复述耗时。**必须由系统计时，不能由模型填**——模型会填个好看的数
- `closedBook`：是否闭卷声明
- `overlapRatio`：与原文的 n-gram 重合度（自动算）
- `rubricHit`：命中了哪几条达标要点（已有，但没校验是否为空）

**维度三：规则约束**
照抄检测怎么算才不误伤？中文技术文本里术语必然重复——如果按字面重合算，正确复述也会被判"照抄"。

## 候选方案

| 方案 | 门禁 | 好处 | 坏处 |
|---|---|---|---|
| A. 只加字数门槛（≥150 字） | 简单 | 一句话过不了 | 凑字数很容易 |
| B. 计时 + 字数 + 照抄检测 | 三道 | 真正挡住敷衍 | 计时需要界面配合；照抄检测有误伤风险 |
| C. 模型判卷（现有 `study_drill` 的 `verdict`）+ 硬性非空 + 字数 | 靠模型 | 灵活，能判断"讲没讲到点上" | 模型可能放水 |

**倾向 B+C 混合**：字数与时长是硬门槛（系统可验证），"讲没讲到点上"由模型判（`rubricHit` 必须非空，`verdict` 必须是三档之一）。照抄检测阈值要实测调，先只做警告不做拒绝，避免误伤。

## 需要用户确认

1. 你愿意接受"复述必须说够 60 秒/150 字才算过"这个门槛吗？还是觉得太硬？
2. 如果系统判你"没讲到点上"，你希望被打回重说，还是只记录不阻挡？
