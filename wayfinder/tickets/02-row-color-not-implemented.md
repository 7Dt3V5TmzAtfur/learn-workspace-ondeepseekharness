# TICKET: 「标注整行有颜色」没有实现

- **状态**: open
- **类型**: `grilling`（HITL — 需要用户确认视觉形态）
- **阻塞**: 无
- **所属**: [MAP](../../map/MAP.md)

## Question

用户原话，两次强调：

> 「注意，这一个标注整一个行是有颜色的，而不是整个段落都是颜色，也不是只有符号有颜色。」
> 「要加除用三种不同的颜色来加粗原文内容」

拆开看，用户要的是**两层**视觉：

1. **渐构标注那一行有背景色** — 让读者扫一眼就知道这段是"定义"还是"例子"还是"提问"
2. **原文里的关键短语用三色加粗** — 注意力机制，不是每句都一样

现实情况：

| 要求 | 现状 | 证据 |
|---|---|---|
| 标注行有背景色 | **只有那个小标签有底色**，整行是透明的 | `.sc-tag{background:var(--dsw-alias-bg-layer-2)}` 只作用在 inline-block 的 span 上 |
| 段落整行底色 | 没实现 | `.sc-seg{border-left:3px solid transparent;...}` —— `data-tier` 属性已经输出到 DOM（37 处），但**没有任何 CSS 选择器用它** |
| 三色加粗短语 | 部分实现 | 37 处 `<strong class="sc-hl-core">` 存在 |
| 三色的颜色区分 | **有 bug** | `.sc-hl-core{border-left-color:#4f8ff7;background:rgba(79,143,247,.10)}` —— `<strong>` 是行内元素且没设 `border-style`，`border-left-color` 无效；只剩 10% 透明度背景，三色几乎看不出差别 |

## 为什么这不是"加个 class 就行"

「整行有颜色」和「整段有颜色」的区别在哪？我要猜出用户的意图：

- **整段变色**（v1 做过，已被否决）：`<section>` 整块上底色，182 段里 37 段有底色 → 大块色斑，读起来眼花，且"哪些字重要"看不出来
- **整行变色**：可能指两种东西
  - (a) 标注**那一行**（标签行）通栏有色，正文行保持白
  - (b) 段落**左侧一条颜色条** + 极淡的行底色，高度与段落齐平

用户先说"整一个行"，又说"不是整个段落"，所以 (a) 更可能是他的意思 —— **标签行通栏着色，正文干净**。

但这只是我的推断，必须让用户确认，因为：
- 如果猜错，做出来的还是"不好看"，白做一轮
- 这个决定影响整个阅读页的视觉基调，是 destination 级别的决策

## 需要用户回答的问题

1. 「整一个行有颜色」是指：标签行（`#d 五类工具的审视特征  Definition` 那一条）通栏有底色，正文不着色？
2. 还是指：每个标注段落的**左侧有一条竖向色条**（像 Gmail 的标签色），正文干净？
3. 还是两者都要？

视觉参考（我可以做 prototype 让用户选）：
- **A 通栏标签行**：`[#d 定义  五类工具的审视特征]` 整条浅蓝底，下面正文黑字
- **B 左侧色条 + 标签**：段落左边 3px 竖条是蓝色，标签行有小色块，正文黑字
- **C 通栏标签行 + 极淡正文底**：标签行彩色，正文 3% 透明度的同色底

## 顺带要修的确定 bug（不需要用户决策）

`.sc-hl-core / .sc-hl-hard / .sc-hl-ref` 三个 class：

```css
.sc-hl-core{border-left-color:#4f8ff7;background:rgba(79,143,247,.10)}
```

问题：
1. `<strong>` 没有 `border-style`，`border-left-color` 完全无效
2. 只有 10% 透明背景，在浅色底上三色几乎分不出来（尤其 core 蓝 vs ref 绿）
3. 深色模式下 `rgba(...,.10)` 的背景比背景色还浅，等于看不见
4. 用户要的是「**加粗**原文」+ 三色。现在只是加了浅背景，字重是 `<strong>` 默认的 bold，还算对；但颜色语义没表达出来

修法方向：用文字颜色 + 下划线（`text-decoration: underline` + `text-decoration-color`）承载颜色语义，背景只做极轻辅助；颜色值走主题 token 而不是硬编码，保证明暗两套都能读。
