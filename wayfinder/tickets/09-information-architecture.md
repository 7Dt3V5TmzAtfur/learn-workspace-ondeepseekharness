# TICKET: 信息架构——4 个 Tab 顺序反向，读前与读中断裂，参考资料从未渲染

- **状态**: open
- **类型**: `prototype`（HITL — 需要看到具体形态才能选）
- **阻塞**: 无
- **所属**: [MAP](../../map/MAP.md)

## Question

界面组评审出的结构性问题（都有代码依据）：

### 1. Tab 顺序与学习流程相反
```js
const [tab, setTab] = useState('read')   // 默认停在"精读加工"
const tabs = [
  { key: 'read', label: '精读加工' },     // 第 1 个
  { key: 'plan', label: '读前建构' },     // 第 2 个
  { key: 'graph', label: '知识图谱' },
  { key: 'quiz', label: '费曼考核' },
]
```
学习第一步是"读前建构"，但它排第 2 且默认不打开。用户一进来看到正文，看不到"我要学什么、怎么考"。

### 2. 读前六段全挤一次渲染，无分节
`preflightHtml` 是 **13,224 字符**，`dangerouslySetInnerHTML` 一次性塞进去。用户要滚 6 屏才能看完六个部分。用户的需求是"① 摘要 ② 帮助与目标 ③ 每部分重难点 ④ 考核方式 ⑤ 思考题 ⑥ 参考资料"——这是**六个独立的东西**，不该糊成一页。

### 3. 读前与读中彻底断裂
`parts[].title`（"第一部分 五类工具的分类"）在精读页**完全不出现**。182 段正文只有 `seg.chapter`（如"工具的分类"）。
用户读第 60 段时：
- 不知道自己在哪个部分
- 不知道这部分的考核要求是什么
- 不知道这部分的重点难点是什么

而这三点正是读前建构的核心产出。**读完就读丢了。**

### 4. 参考资料从未渲染
`refsHtml`（803 字符）和 `refs[]` 在 client.js 里**搜不到任何引用**。用户明确要求第 6 部分要有参考资料列表（标注 原文/我的知识/联网检索），数据生成了、HTML 也渲染了，但界面不显示。

### 5. 表格渲染崩坏
宿主把 Markdown 表格逐行转成 `<p>`：
```html
<p>| 工具类型 | 调用方向 | 作用对象 |</p>
<p>|---------|---------|---------|</p>
```
界面上是一列竖排竖线。而这本资料的表格正是核心内容（五类工具表、四层应对手段表）。

## 三个维度的思考

**维度一：用户认知负荷**
用户打开工作台，第一个问题不是"正文在哪"，而是：
- 这份资料讲什么？（摘要）
- 我要达到什么程度？（目标）
- 怎么判断我学会了？（考核方式）

这三个问题答完，才有心情读正文。现在的界面**默认跳过了这三个问题**。

**维度二：信息架构的组织轴**
现在按"内容类型"分 Tab（精读/读前/图谱/考核）。但内容类型不等于用户任务。
用户任务是**有顺序**的：先知道要学什么 → 再读 → 再连线 → 再自测 → 再考核。
所以 Tab 应该按**阶段**排，且顺序与流程一致。

但"读前"这一项有 6 个子内容，13KB，塞一个 Tab 会撑爆。需要**二级导航**。

**维度三：读前与读中如何连通**
关键洞察：`parts[]` 是桥梁。它有：
- `title`（第一部分 五类工具的分类）
- `assessment`（要求、目的、掌握档）
- `keyPoints` / `difficulties`
- `knowledgePoints`（知识点+内容+备注）

而 `segments[]` 有 `chapter` 字段。
需要做的是：**把 segments 归属到 parts**，然后读中页面顶部显示"当前部分"的考核要求卡片。

怎么归属？两个方案：
- A. 让模型在 preflight 时给每个 part 标 `segmentRange: ['¶1','¶60']`
- B. 用 `seg.chapter` 与 `part.title` 模糊匹配

A 更准但要改数据；B 不用改但会错配。倾向 A，并在 `study_save kind=preflight` 时校验 range 合法。

## 候选方案（需要用户选）

### 方案 1：总览 + 4 阶段 Tab（界面组建议）
```
[总览] [① 读前] [② 读中] [③ 图谱] [④ 考核]
```
- 总览：摘要卡 + 目标卡 + 四部分进度表 + 下一步按钮
- 读前：左目录 6 项 + 右侧单节渲染
- 读中：左"章节→段落"树 + sticky 当前部分要求卡 + 右段落流

优点：符合学习流程，解决断裂
缺点：多一层 Tab，"总览"和"读前"有内容重叠

### 方案 2：两栏——左流程导航，右内容（单页滚到底）
```
┌ 流程导航 ┬──────────── 内容 ────────────┐
│ ① 摘要   │  当前选中内容                  │
│ ② 目标   │                                │
│ ③ 部分1  │                                │
│ ④ 部分2  │                                │
│ ...      │                                │
│ ⑧ 读中   │                                │
│ ⑨ 图谱   │                                │
│ ⑩ 考核   │                                │
└──────────┴────────────────────────────────┘
```
优点：一屏只有一个概念"第几步"，最清晰
缺点：左侧导航项太多（10+），且"读中"（182 段）和其他项体量差太多

### 方案 3：顶部阶段条 + 单页，读前折叠
用现有 4 Tab，但：
- 顺序改为 读前 → 读中 → 图谱 → 考核
- 默认打开读前
- 读前内部用 `<details>` 折叠，默认只展开前两节
- 读中页顶部加"当前部分"卡片

优点：改动最小，一周能做完
缺点：没有"总览"，用户还是要自己拼
