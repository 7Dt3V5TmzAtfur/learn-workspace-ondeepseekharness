# TICKET: 引入"反向覆盖审计"——回答"我是不是真的读全了"

- **状态**: open
- **类型**: `grilling`（HITL — 需要决定做多重）
- **阻塞**: 无
- **所属**: [MAP](../../map/MAP.md)

## Question

参考项目 `learn-from-materials` 最值得学的一条设计：**覆盖要能反查，不是正着数产出**。

- 正向：逐个原文块标记"被哪个输出单元覆盖了"
- **反向**：从原文块反查——**有多少块没被任何输出覆盖？未映射率必须为 0**

我现在的系统完全没有这个概念。后果：

- chapter4 有 **182 段**，标注只覆盖 **37 段**。剩下 145 段去了哪里？
- 系统里没有任何地方能回答这个问题。用户看不到"还有 80% 没加工"
- 六段式 preflight 的 `parts` 有 4 个部分，但这 4 个部分是否覆盖了全部 182 段？没人验证过

## 为什么这个缺口很严重

用户学的是技术书，最怕的是**以为自己读完了，其实漏了一半**。这正是原则原文 `知识占有错觉.md` 和 `收藏不等于拥有_未读积压是自我否定.md` 批判的：

> 「收藏不等于拥有」

我现在让用户"导入"了一份资料，界面上显示"标注 37 条"，看起来做了什么，但**没有任何一处告诉他 145 段没读**。

## 三个维度的思考

**维度一：用户视角（这是不是一个可以展示的数字？）**
"未加工 145/182 段"——这个数字是**压力**还是**噪音**？
- 如果展示为红色警告，用户会觉得被指责，可能干脆放弃
- 如果展示为"已加工 37/182，还剩 145"，是客观进度

关键区别：**指向"还有什么可做" vs 指向"你没做完"**。

而且要注意：**不是每段都值得标注**。`study-annotate` 技能明确说"不值得就不标（不标是正常且正确的选择）"。所以"145 段未标注"里，可能有 100 段本来就不该标。

那就需要区分：
- **未"看过"**（真的没读）← 这是问题
- **看过但判定不值得标**（主动跳过）← 这是正常

**维度二：数据结构**
要区分上面两者，必须记录"这段被评估过了，结论是不值得标"。现在没有这个字段。

最小实现：
```json
// annotations.json 增加
{
  "items": [...37 条...],
  "skipped": [
    { "segmentId": "¶2", "why": "过渡句，无独立知识点" },
    ...
  ]
}
```
`coverage = (items.length + skipped.length) / totalSegments`

**维度三：规则约束**
要不要强制 100%？参考项目是"未映射率必须为 0，否则阻止渲染"。
但这在长文档上不现实——145 段逐段写跳过理由，标注工作量翻 4 倍。

折中：
- `coverage < 100%` → 只显示进度，不阻塞
- 但**如果用户声称"读完了"要进入考核阶段，则要求 coverage ≥ 95%**（要么标了，要么明确跳过）
- 这个门槛要用户确认

## 参考项目做得过重的地方（不要抄）

它搞了三层账本（coverage-audit + reverse-coverage + summary-ledger），同一条主张在 4 个地方各记一遍。调研结论原话：

> 「3 页示例材料产出 11 个候选 + 4 scope + 2 份 structure-review + 6 张方法卡，**审计体量超过知识体量**」

所以：**只做一层**。一个 `skipped` 数组 + 一个覆盖率数字，不做 claim 级映射。

## 需要用户确认

1. 界面上要不要显示"已加工 37/182 段"这个数字？
2. 如果显示，你希望它是中性进度条，还是带提醒（"还有 145 段没处理")？
3. 进考核前，要不要强制 coverage ≥ 95%？
