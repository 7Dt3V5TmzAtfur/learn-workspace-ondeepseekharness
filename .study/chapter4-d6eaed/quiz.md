# 思考题与作业（费曼学习法）

> 闭卷前提：先合上原文，用 60 秒讲清「本章把工具设计拆成两个常被混为一谈的决策：能力做成什么形态，以及一次让模型看见多…」

## 1. 合上文档，不查原文，写出：（1）能力形态谱系的两端各是什么，各自代价是什么；（2）工具太多时的四层应对手段，按“按需程度”从低到高排。

- 类型：回想
- 达标要点：专用工具 vs Skill 两端说对；分别说出常驻 token 代价；四层顺序正确（层次化/按需加载→检索预筛选→主动发现→Skills）
- 最小行动：现在合上文档，在纸上画表格填三列（形态两列、披露四层），写完再对

## 2. 向一个没读过本章的工程师解释：为什么作者反复强调“形态”和“披露”是两个独立决策？用一个具体例子说明四种组合都真实存在。

- 类型：解释
- 达标要点：说清形态定常驻成本、披露定同时可见数量；举出“几百个专用工具但只暴露索引”这个组合；指出把两者混为一谈的常见错误
- 最小行动：打开语音备忘录问自己这个词，录一段 60 秒，回放听哪里卡住

## 3. 找你正在写的一个 Agent 项目（或本学习系统），逐条看它的工具定义：哪些应该合并、哪些应该退回专用工具、哪些该改写成 Skill？给出至少三条具体建议并说明依据的是哪个决策维度。

- 类型：应用
- 达标要点：至少三条建议；每条都指出了依据的决策维度；有可操作的改法而不是方向性表态
- 最小行动：只改其中一处，改完对比读一遍，记录 token 变化

## 4. 本章的“能力形态谱系”和“层次化披露”能不能搬到你熟悉的另一个领域？例如公司的 API 网关设计、或图书馆的分类检索。说清对应关系，并指出迁移后会失效的地方。

- 类型：迁移
- 达标要点：领域是本章没提的；能对应上“常驻成本 vs 按需发现”的同一个张力；指出失效之处（如该领域没有 token 预算这个约束）
- 最小行动：把那个对应关系写进备忘，下次设计接口前先看

## 5. 本章引用了多个漂亮的数字（token 减 46.9%、准确率 49%→74%、节省 98%）。这些数字支撑的结论有多强？挑一条，说明它能证明什么、不能证明什么。

- 类型：批判
- 达标要点：指出数字来自特定模型/特定基准，不可外推；区分“在这套基准上”与“在真实任务上”；说出还需要什么证据才能把结论推广
- 最小行动：列一条你自己想追问作者的问题

## 6. 回想你过去设计工具或写脚本的方式，本章哪一条原则是你一直在违反的？具体是哪一次？

- 类型：反思
- 达标要点：指出具体的过去案例；能对应到本章某条原则；说出今后打算怎么做
- 最小行动：写一句话：你现在的默认做法是什么，打算改成什么
