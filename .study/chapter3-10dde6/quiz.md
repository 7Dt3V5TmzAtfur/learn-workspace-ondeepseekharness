# 思考题与作业（费曼学习法）

> 闭卷前提：先合上原文，用 60 秒讲清「上一章管单次交互的上下文，这一章要解决对话结束后 Agent 还能不能记住人、记…」

## 1. 合上资料，说出用户记忆的三层次评估框架每一层各考察什么，并各举一个你自己想的、原文没有的例子。

- 类型：回想
- 提示：第三层的判断标准：用户有没有明确要求你做这件事。
- 达标要点：三层名称正确：基础回忆、多会话检索、主动服务；能说清基础回忆考察的是结构化无歧义信息的精确存取，而非难易程度；每层举出的例子确实属于该层（判断标准看是否跨会话、是否有明确指令）；能说出主动服务的本质是“无明确指令下的预见性”
- 最小行动：明天花 5 分钟，用手机备忘录写下三个例子，各标一句“为什么属于这一层”。

## 2. 向一个完全不懂向量的人解释：为什么混合检索要用 RRF 融合，而不是把余弦相似度和 BM25 得分加权平均？不许用“归一化”这个词。

- 类型：解释
- 提示：想想两种考试的分数——一个满分 1 分，一个满分没上限，你怎么合？
- 达标要点：说清两路得分的取值范围与分布不同（余弦 0-1，BM25 0 到几十且无上界）；指出加权平均需要先知道两路该怎么换算，而这个换算关系不稳定；解释 RRF 只取排名，天然绕开了尺度问题；能说出 RRF 的代价：丢掉原始得分里的相关性强弱信息
- 最小行动：明天把这段解释写成一个 200 字的微信消息发给朋友，看他能不能听懂。

## 3. 某知识库有 500 份产品手册，用户常问“退款政策是什么”这类单点查找，也偶尔问“A 型号的散热方案和 B 型号在架构上有什么区别”。你会怎么配置检索？说明每一层的选择理由和多花的成本。

- 类型：应用
- 提示：原文给了一个判断标准：查询是“找到包含某信息的片段”，还是需要“跨文档综合”或“多层次导航”。
- 达标要点：对单点查找给出混合检索（稠密＋稀疏＋重排序）即可，并说明理由；对跨文档综合类查询指出混合检索不够，需要 RAPTOR 或 GraphRAG 一类结构化索引；说明结构化索引的代价是索引构建与查询时都需要更多次 LLM 调用，延迟和成本显著增加；给出可行的折中（如先上混合检索，按查询类型路由到结构化索引）
- 最小行动：明天用 10 分钟，把你手头项目的查询日志翻一遍，数一数两类查询各占多少比例。

## 4. 本章反复出现的“把知识当成代码库、把变更当成 PR”这套模式，还能用在什么别的地方？举一个原文没提的场景，并说清为什么它仍然成立。

- 类型：迁移
- 提示：想想任何需要多人持续修改、且错了要能追责回滚的文档体系。
- 达标要点：举出的场景确实有“多条证据持续涌入、需要可追溯修订”的特征；能对应上提议者—审核者、分支隔离、可回滚这三个要素；说清该场景中“原始证据层”与“知识层”分别是什么；指出异源审核或证据可追溯在其中仍然必要
- 最小行动：明天写下这个场景的三层结构和一次假想的 PR 流程，一页纸即可。

## 5. 本章说结构化索引值得投入，也说未经提炼的原始知识无法可靠利用。但 GraphRAG 的语义降级恰恰说明“结构化会丢信息”。这两句话矛盾吗？如果不矛盾，你在什么条件下选择结构化、什么条件下选择保留自然语言？

- 类型：批判
- 提示：注意原文推荐的是“分层互补”而不是二选一。
- 达标要点：能指出两句话针对的是不同对象：前者针对“完全不加工”，后者针对“过度结构化到三元组”；引用原文的分层互补结论：以自然语言保存核心信息，结构化元数据仅用于索引检索；给出判断条件（是否需要多跳推理、精确消歧，信息是否含条件与时间依赖）；能指出原文在此处的论证依赖个案举例，缺少量化边界，这是可质疑的地方
- 最小行动：明天写三句话：我的场景里哪类信息必须保自然语言，哪类可以转三元组，为什么。

## 6. 原文说匿名用户的记忆系统在“主动服务”层最难。假设你要向老板论证这套双层记忆架构值得做，用原文的数据和论证说明：投入多少、换来什么、风险在哪里。

- 类型：迁移
- 提示：把本章的实验编号当成你的证据清单。
- 达标要点：能引用上下文感知检索的具体收益数据（结合 BM25 降失败率 49%，加重排序 67%）；说清双层架构分别是哪两层、各自解决哪种层次的评估用例；指出成本侧：索引期额外 LLM 调用，prompt caching 可压到每百万文档 token 约 1 美元；指出风险侧：Mem0 v3 那类“错误 UPDATE 不可逆丢历史”的教训，或知识库投毒、间接提示注入
- 最小行动：明天列一张两列清单：左边我能量化的收益，右边我还没把握的风险。
