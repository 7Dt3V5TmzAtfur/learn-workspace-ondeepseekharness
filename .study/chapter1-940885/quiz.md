# 思考题与作业（费曼学习法）

> 闭卷前提：先合上原文，用 60 秒讲清「Agent = LLM + 上下文 + 工具，而这三个词每个都决定了能力边界在哪」。讲不下去的地方，就是下面该动笔的地方。

## 1. 合上文档，不查原文，写出：（1）Agent 的三组件公式和它的直觉版；（2）为什么 Environment 不算在里面；（3）观察空间与动作空间各决定什么。

- 类型：回想
- 达标要点：公式与「大脑+眼睛+手脚」都对；说出"环境是闭环的另一方，Harness 可以代理它但不含它自身"；说出"没进上下文=不存在，没被允许=只能停在文字建议"
- 最小行动：现在合上文档，在纸上画一个圈写 Agent、外面写 Environment，标出两条箭头

## 2. 向一个没读过本章的产品经理解释：为什么"升级到更强的模型"经常解决不了 Agent 做不好任务的问题？

- 类型：解释
- 达标要点：说清两个可能——信息没进来（眼睛问题）或操作没被允许（手脚问题）；指出这两种情况下换模型无效；举一个"把数据接进去就好了"的具体例子
- 最小行动：打开语音备忘录，录 60 秒，回放听你在哪里卡住

## 3. 把 ReAct 循环的一轮完整走一遍：假设让 Agent 汇总三个城市今天的天气。写下第 1 轮的静态前缀、轨迹、模型输出、工具结果各是什么；再写第 2 轮相比第 1 轮，上下文多了什么。

- 类型：应用
- 达标要点：正确区分静态前缀（系统提示词+工具定义）与轨迹；指出第 1 轮轨迹里只有用户消息；说清工具结果是追加到轨迹末尾的
- 最小行动：不查原文写一遍，写完再回去对 ¶67-¶82 那个多币种汇率的例子

## 4. 本章说「模型固定时，扩展观察空间与动作空间往往是最主要的系统工程手段」。举一个你自己遇到过的例子：某个 AI 工具"看起来很笨"，但其实只是没拿到需要的信息、或没有需要的操作。

- 类型：迁移
- 达标要点：例子是真实的、不是编的；能明确判断属于眼睛还是手脚；说清补上之后为什么就变好了
- 最小行动：把这个例子记下来，下次遇到"AI 不好用"先按这个清单查一遍

## 5. 拿一个你每天在用的 AI 产品（不是本章举例的那五个），用「眼睛 / 手脚 / 策略」三个维度拆开。拆完回答：如果只允许你改一个维度来提升它，你改哪个，为什么？

- 类型：批判
- 达标要点：三个维度都有具体内容而非空话；最后的取舍有理由、指向真正的瓶颈；能指出"改这个而不是那个"的代价
- 最小行动：写完后找一个也用这个产品的人，问他的判断是否一致

## 6. 本章说 Demo 和产品之间的鸿沟要靠约束、验证、纠正来填。挑一个具体的故障场景（比如 Agent 反复调用一个不存在的工具，或遇错后不断重试直到耗尽预算），说明该由哪一层来兜、具体怎么做。

- 类型：应用
- 达标要点：正确归到约束/验证/纠正中的一层；给出可操作的机制而非方向性表态；能说出为什么不是另外两层
- 最小行动：在你熟悉的系统里找出一个类似的缺口，写一句话描述它现在靠什么兜

## 7. 工作流和自主 Agent 的判据是"任务的可预测性"。找一个你正在做的任务，判断它该用哪种，并说出如果判断错了会付出什么代价。

- 类型：迁移
- 达标要点：判据用对了（步骤能否预先固定）；说清用错的两种代价——工作流遇到预设外情况时无路可走，自主 Agent 则成本与复合错误风险更高
- 最小行动：如果这个任务已经在做，写下你现在用的是哪种，是否需要换

## 8. 三级护栏按"被绕过的难度"排而不是按处理顺序排。这个区分重要在哪？如果按处理顺序排会得出什么错误结论？

- 类型：批判
- 达标要点：指出按难度排是为了让下层不依赖模型判断；说出按时间排会误以为"先过后过都行"或"上下文层过了就安全"
- 最小行动：画一条竖线标三层，在每层旁边写"它靠什么生效"

## 9. 人工干预要求 Agent 能"优雅地移交控制"。但用户可能不在线、响应很慢、或给出模糊指令。这时 Agent 应该怎么办？请给出你自己的方案。

- 类型：批判
- 达标要点：识别出这是原文留作思考题、没有标准答案的开放问题；方案要处理"等多久""谁来兜""降级到什么状态"；不回避"用户永远不回来"这个最坏情况
- 最小行动：写下你的默认策略（比如超时后走保守分支），并说明代价

## 10. 本章说"适配层会随模型变强被内化"。你的工作里现在有哪些环节属于这种"给模型短板打补丁"的适配层？如果模型明天变强了，哪些会失效？哪些不会？

- 类型：反思
- 达标要点：至少列出两处自己工作中的适配层；区分"补能力短板"（会失效）和"约束风险"（不会失效，如权限、审计）；说出这对你规划工作的影响
- 最小行动：把列出来的项目标上"半年内可能失效"，只对不会失效的那些加深投入

## 11. 五个设计模式里，哪一个和你的直觉最冲突？为什么？如果要用它，你现在的做法需要改哪一步？

- 类型：反思
- 达标要点：指出具体是哪个模式；说出冲突在哪（而不是泛泛说"很难"）；给出一个具体的改法
- 最小行动：在下一次代码或文档评审里，主动试用这一个模式一次

## 合卷复述（最后一步，必须做）

合上全部资料，对着一个不懂技术的人讲清三件事，全程不超过 3 分钟：

1. Agent 是什么——用「大脑 + 眼睛 + 手脚」讲，不许用 LLM、上下文、工具这三个词
2. 为什么 AI 有时很笨却不是模型的问题
3. 为什么"能跑"和"可靠"之间隔着很远

讲完录下来。卡住的那处，就是你还没真掌握的地方——回去读那一段，不要重读全章。
