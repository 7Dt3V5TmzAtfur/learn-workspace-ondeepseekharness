# 学习资料 AI 辅助系统 · 架构设计

> 目标：上传任意格式文档 → 读前建构 → 读中加工 → 读后考核，全程遵循 `原则/` 目录中的学习规律。

## 0. 第一性原理

这条决定其他所有取舍，写在最前面因为后面每一节都是它的推论。

**错误的第一性原理**（本系统前三版实际在做的）：
> "要帮用户把这资料学完。"

推论出来必然是：覆盖率、高亮占比、每段都标、QA 至少 6 条。
为了把覆盖率从 1.6% 刷到 11%，会给每段机械找一句话，
产出「维度」「按需」「比单写」这种 4 字碎片 ——
界面更满、更难看、用户一个点都没记住。那是**负价值**。

**正确的第一性原理**（`原则/C1.03.b/反完成主义阅读.md`）：
> 帮用户从一份资料里拿到**能改变他行为的那几句话**。

三条推论，直接决定了三处设计：

| 推论 | 设计后果 |
|---|---|
| 进度不能是"完成了多少" | 主指标是「已经拿到 64 处能复述的要点、12 道自测」，不是「已标 182/182 段」 |
| 入口必须是"我想解决什么" | 读前六段式第②段先问"对我的帮助"，不是先给目录 |
| 摩擦必须极低 | 六段式默认只给 2796 字骨架（原 5845 字），细节折叠；单元目录默认收起 |

**不做什么**（和"做什么"同样重要）：
- 不设"每单元必须有 N 个知识点"这类配额 —— 一旦有配额，模型就会凑。
- 不把覆盖率做成阻断 —— 覆盖率只提示，永远不拦。
- 不做多层审计文书 —— 参考项目给它自己的产物配了 10 个审计账本，
  那是完成主义的另一种形式。用户原话："弄得太复杂就不想看书了。"

## 1b. 三层拆分

```
┌─────────────────────────────────────────────────────────────┐
│  界面层  Client 插件  @local/dsh-study-copilot (client.js)    │
│  ├ 侧栏面板 "学习工作台"（main 面板，key = study-copilot）    │
│  ├ 输入框停靠条：当前文档 · 阶段 · 下一步                      │
│  ├ 三色注意力阅读器（渲染宿主给好的 HTML）                     │
│  ├ 术语追问（选中文字 → 带 ¶N 上下文）                        │
│  ├ 知识图谱（iframe 嵌入 archify 生成的 HTML）                 │
│  └ 费曼考核 / 读前建构                                        │
├─────────────────────────────────────────────────────────────┤
│  能力层  Host 插件  @local/dsh-study-copilot (index.js)       │
│  ├ 多格式提取  extract.js（pdf/docx/pptx/xlsx/html/epub/…）   │
│  ├ 项目存储    store.js    <workspace>/.study/<docId>/        │
│  ├ 规则校验    rules.js    标签/三色预算/六段式/目标分级       │
│  ├ 内容渲染    markdown.js Markdown→HTML（短语级高亮）         │
│  ├ 图谱生成    archify-figures.js → archify CLI → HTML        │
│  ├ Agent 工具  study_ingest · study_read · study_save         │
│  │             study_term · study_status · study_drill        │
│  ├ HTTP API    /study-copilot/api/*（数据 + 图片资源）         │
│  └ 提示词段落  systemPrompt.section（声明工作流）              │
├─────────────────────────────────────────────────────────────┤
│  方法层  技能  .dsh/skills/study-*                            │
│  study-companion 总控 → preflight → annotate → map            │
│                     → recall → explain-term → feynman         │
└─────────────────────────────────────────────────────────────┘
```

**为什么这样切分**

- **插件 = 机制，技能 = 方法。** 提取格式、落盘、算覆盖率、渲染三色、算图坐标，这些是确定性计算，写成插件；"怎么拆解语义、怎么定重难点、怎么出思考题"是判断，写成技能让模型执行。两者不重叠。
- **同一个操作两个调用者。** 界面上的"导入文档""保存标注"和 Agent 的 `study_ingest`/`study_save` 调的是同一个 Host 服务方法（`StudyService.*`），没有两套逻辑。
- **界面不自己算，也不自己解析。** 宿主返回的 `/project` 里，每段都带渲染好的 `html`
  （高亮已经嵌在里面），图谱给出 `figures[]` 的 URL。界面只做三件事：插入 HTML、填 iframe 的 src、处理点击。
  这样"什么算粗体""标签怎么折行"只实现一次。**这条是踩过坑之后加的**：早期版本让客户端
  自己逐行输出 `<p>`，结果是粗体显示成字面星号、表格塌成一堆竖线、图片显示成链接源码。
- **技能可单独使用。** 不安装插件时，技能仍能靠纯文本工作（降级路径在技能里写明）。

### 2.1 单元骨架（v4 新增，把三处断裂接起来）

在此之前有三个同一病根的断裂，都是"182 段平铺、没有中间层"：

| 现象 | 修复前 |
|---|---|
| 知识点无法跳回原文 | 18 个知识点，0 个带 `segmentIds` |
| 图谱节点与段落脱钩 | 33 节点，0 个带 `segmentId` |
| 读前 parts 是模型编的切法 | 4 个 parts，0 个带 `segmentIds`；原文有 20 个真实小节 |

`units.json` 是中间层：**原文小节 → 段落 → 知识点** 靠它串成一条线。

切块规则（`tests/build-units.mjs`）：

1. 认两种小标题：Markdown `## 标题` **和** 加粗单独成段 `**小标题。**`。
   只认第一种会切出 45 段与 2 段并存的不均衡块。
2. 大标题下不足 300 字 → 合并紧跟的加粗小节（否则出现点进去什么都没有的条目）。
3. 合并后超过 2500 字 → 不合并，各小节独立成块。
4. 标题去掉末尾句号。
5. 生成时自校验五项：不重、不漏、无空块、有原文范围、大小不失衡（≤40 倍）。
   不过就拒绝写文件。

当前结果：25 块 / 182 段，中位 809 字，最大/最小 33.9 倍。

### 2.2 回指（每条知识点的来路）

`preflight.json` 的每条 `knowledgePoints[]` 带：

- `segmentIds` —— 原文段落号，界面渲染成「看原文 ¶N」，点了跳过去并闪一下
- `mappingSource` —— `manual` | `auto`，标明这条是怎么定位的

**找不到就不挂**，界面显示灰色「原文位置待定位」。
原则：挂错比不挂更糟 —— 用户点「三层防护」跳到讲 MCP 投毒的段落，
会以为自己记错了。所以自动匹配之上还有一张人工覆盖表。

**读前六段式**（对应第 1–6 项要求）

1. `summary` — 300 字左右摘要
2. `goals` — ①这份资料对我（学习者）的帮助（第一、第二） ②总目标 ③子目标
3. `difficulty` — 每一部分的重点、难点
4. `assessment` — 每一部分的考核方式（了解/理解/掌握/熟练掌握 + 目的 + 达标要求）+ 知识点与内容、备注
5. `exercises` — 思考题与作业（费曼驱动）
6. `references` — 参考资料清单

界面上 ③④ 的细节默认折进 `<details>`：5845 字 → 默认可见 2796 字（-52%）。

## 3. 阅读中的三色注意力

七色语义（`多色编码阅读标记.md`）收敛为三档，避免"每句都标 = 没标"：

| 档位 | 颜色 | 语义来源标签 | 用途 | 预算 |
|---|---|---|---|---|
| 1 核心 | 橙 `--sc-core-line` `#f59e0b` | `#d` 定义 / `#s` 结论 | 必须能复述的骨架 | ≤ 全文 10% |
| 2 攻坚 | 品红 `--sc-hard-line` `#c026d3` | `#q` 疑问难点 / `#v` 验证 | 必须停下来想的地方 | ≤ 全文 8% |
| 3 参考 | 青 `--sc-ref-line` `#14b8a6` | `#e` 例子 / `#t` 迁移 / `#c` 备注 | 需要时回查 | 不限，但不参与精读 |

深浅两套主题各有一组 token（浅色深字 `--sc-*-fg` 配浅底 `--sc-*-bg`，深色反过来），
行底色是 `--sc-*-row`。

**来源说明（必须诚实）**：

- **来自 `原则/` 的是**：七个渐构角色标签（`#d/#s/#q/#v/#e/#t/#c`）、
  预算上限 10–20%（`深度阅读的二八法则.md`）、"高亮必须落在原文短句上"。
- **我们自己定的、原则里没有的**：把七色**收敛成三档**、
  以及具体选**橙/品红/青**这套配色。原则只给了七类语义，
  没规定收敛成几档、也没规定颜色。
  这样做的理由：档位超过三档，用户在阅读中无法即时判断归属；
  颜色超过三种，视觉噪点会盖过语义本身。

插件在保存标注时校验：总高亮占比 ≤ 20%（二八法则），每段至多 1 个档位，
`#c` 标签必须带两字关键词，且 quote 不能是 ≤6 字的碎片
（`FRAGMENT_QUOTE_MAX_CHARS`，纯标题段豁免）。

## 4. 六个阶段（状态机）

```
ingested ──preflight──▶ planned ──annotate──▶ annotated ──map──▶ mapped
   导入        读前建构         读中标注            知识图谱
                                      │
                                      ├──qa──▶ recalled ──drill──▶ drilled ──▶ done
                                      │        读后自测              费曼考核
                                      └─（terms 随时记录，不占阶段）
```

图谱与自测都只依赖 `annotated`，可以任选顺序；`quiz.md` 在读前就生成，
所以"考核"阶段只由 `drills.jsonl` 的真实记录点亮。

每个阶段插件都返回"下一步该调什么"，技能里写明该阶段要交付什么、达标标准是什么。

## 5. 界面设计

**入口**：左侧栏新增一个书本图标（`sidebar.panellist` id = `study-copilot`），点击进入主面板。
**主面板**：四个 Tab —— 精读加工 / 读前建构 / 知识图谱 / 读完自测 + 费曼考核。
**输入框停靠条**：显示当前文档 + 阶段 + 「继续」按钮，随时知道读到哪。

**精读页（Tab 1）的层次**，从上到下正好是用户心里的三个问题：

| 位置 | 内容 | 回答的问题 |
|---|---|---|
| 顶部单元目录（默认收起） | 「这份资料分 25 块 · 182 段」，每行一块带段数与要点数 | 这资料讲几件事？ |
| 图例行 | 三色语义 + 「分 25 块，25 块已看过」 | 我在哪？ |
| 正文 | 逐段三色高亮，核心档默认盖住待回想 | 这一段说什么？ |

单元目录刻意默认收起：想直接读的人不该被目录挡路。
图例里不放完成度百分比 —— 那会让人为了填满去标碎片。

**读前页（Tab 2）**
- 六段式按 ①②③④⑤⑥ 分块，左侧竖排导航
- ③④ 的细节折进 `<details>`：5845 字 → 默认可见 2796 字
- 每个知识点右侧「看原文 ¶N」→ 切到精读页、滚到那一段、闪 1.6 秒
- 没有回指的知识点显示灰色「原文位置待定位」，不给假链接

**渲染职责划分**

| 内容 | 宿主产出 | 界面动作 |
|---|---|---|
| 段落正文 | `segments[].html` | 插入 HTML |
| 六段式 | `preflightHtml` | 插入 HTML + 事件委托接「看原文」 |
| 思考题 / 参考 | `quizHtml` / `refsHtml` | 插入 HTML |
| 图谱 | `figures[]`（archify HTML 的 URL） | `<iframe src>` |
| 图片 | `/asset/<docId>/<path>` 路由 | `<img src>` |

**术语追问（对应 3min.top 那种"指着词就问"）**
- 选中正文任意词 → 面板右下浮出气泡，显示选中的字 → 点「问这个词」
- 选区取值必须用 `getSelection().toString()`（写成 `String(selection)` 会拿到 `[object Selection]`）
- 语音提问走 Harness 自带语音输入：追问框获取焦点后按下麦克风即可说话
- 回答必须结合**当前段落上下文**：提问时自动带上 `¶N` 段落原文

**知识图谱**
- 嵌的是 **archify 生成的 HTML**，不是 Mermaid 源码，也不是手绘 SVG
- `relations.json` 保存成功后宿主自动调 archify，产物 `graph-N.html` 落在 `.study/<docId>/`
- 超过 18 节点按根节点自动拆图：archify 的 `browser-check` 会按视口缩放判断字号可读性，
  33 节点铺 4348px 宽缩到 1440 后 12.5px 字变成 4px，会被判定不可读而拒绝出图
- 界面上方一排按钮切换子图，下方 `<details>` 列关系清单，附"新窗口打开"
- 出图失败不阻塞阶段推进（关系数据已存好），界面显示失败原因

**三色高亮**
- 宿主端在段落 HTML 里把 `quote` 逐字命中处包成 `<strong class="sc-hl-{tier}">`
- 界面按 `data-id="¶N"` 切出每段 HTML，用 `dangerouslySetInnerHTML` 插入
- 段落本身**不染色**（`<section class="sc-seg">` 没有颜色 class）——整段变色等于没标

## 6. 测试策略

| 层 | 测什么 | 用例 |
|---|---|---|
| 提取 | 10 种格式都能出正文、中文不乱码 | `tests/run-tests.mjs` §1 |
| 分段 | 段落切分不碎不黏 | `§2` |

| 语义 | 生成思考题 ≠ 完成考核 | `§7` |
| 无损 | 工具返回值必须是无损 JSON | `§8` |

| **高亮** | **quote 必须逐字在原文、预算按 quote 字数算、段落不整段染色** | **`§11`** |
| **需求** | **用户提的需求逐条断言** | **`tests/audit-requirements.mjs`（29 项）** |
| **接口** | **真实 HTTP：图能取到且是 HTML、越界被拒、QA 能存能读** | **`tests/e2e-check.mjs`** |
| **界面** | **渲染出来的内容对不对（不是接口 200）** | **`tests/audit-ui.mjs`（88 项）** |
| **技能文档** | **7 个技能的约束是否写进文档** | **`tests/audit-skills.mjs`（33 项）** |
| **样式** | **class 有没有样式、CSS 变量有没有悬空** | **`tests/audit-styles.mjs`** |
| **切块** | **单元不重不漏、有原文范围、大小不失衡、标题无句号** | **`tests/build-units.mjs` 自校验** |
| 图谱质量 | 几何指标 + Pillow 预览图 | `tests/check-graph-quality.mjs` |

**两条教训**（都是踩过的）：

1. 只断言"接口 200"和"HTML 里出现 class 名"是不够的 ——
   这两个都通过时，界面仍然可能一个字都不显示。
   测试必须断言**输出的内容**（粗体是不是 `<strong>`、
   表格是不是 `<table>`、边有没有穿过节点）。
