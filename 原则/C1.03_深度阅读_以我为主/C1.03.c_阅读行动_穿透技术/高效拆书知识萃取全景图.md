# 拆书流程

> 第一性原理: 保持“**多次反复，联想回忆**”的底层原则，工具只是提效，你的“灵魂三问（目的、用法、对比）”才是这套流程里最值钱的部分

### 1. 【物理-文件拆分层】PDF 转 Markdown 的“提效神器”

| 步骤              | 操作动作                      | 关键工具                         | 核心目的/备注                                        |
| :---------------- | :---------------------------- | :------------------------------- | :--------------------------------------------------- |
| **1. 格式转换**   | PDF转Word，修正格式错误       | `PDFelement-12` + OCR            | 去除格式干扰，提取纯净文本。                         |
| **2. 格式标准化** | Word转Markdown                | `Pandoc`                         | 转换为通用笔记格式，便于后续处理。                   |
| **3. 章节拆解**   | 建立仓库，按H1/H2标题拆分文件 | `Obsidian` + 插件`Note Refactor` | **化整为零**：将大书拆解为子章节文件，便于独立阅读。 |

pdf用`PDFelement-12.0.8.3784+OCR-CN-Portable`转成word文档，去掉部分格式错误

word文档用pandoc 转换为markdown文档

工具——**MinerU (Magic-PDF)**， 转换部分清晰书籍

**文稿副本拆解**：新建obsidian仓库，安装核心插件`Note refactor`，设置default local 位置为新文件夹。按照split note by headings h1 和 h2 分别拆解，建立子章节文件夹。

新建目录文件，用obsidian双链，构建拆分后的目录导航，到二级或三级标题。

### 2. 【宏观-辅助阅读层】 逻辑框架 Prompt 扩展

| 分析维度 | 提示词示例                                            | 操作技巧                 | 使用工具                             |
| :------- | :---------------------------------------------------- | :----------------------- | :----------------------------------- |
| 排序     | “本书这8个部分的阅读顺序应该是怎么样的？”             | 分析一级章节的逻辑串联。 | `Google AI Studio`<br>(Gemini 3 Pro) |
| 逻辑     | “下面是‘控局’部分，共4个章节，帮我分析内部逻辑关系。” | 分析二级章节的内部联系。 | 同上                                 |

用Google AI Studio的免费gemini3 pro的大模型，整理章节之间的关系。

首先是，所有一级章节的阅读关系, 所有二级章节内部关系。

`下面是书籍中的“控局”部分，共4个章节，帮我分析一下章节之间的内部逻辑关系。`

- 用vscode打开最开始的markdown全文，通过折叠一级标题，可以快速选中该章节所有内容，放到上述prompt的后面，用google ai studio的好处是可以处理超长文本。

1. 框架AI辅助清晰逻辑
2. 一页清+iOS18设计风格打印框架 [xxx理论框架图] ，打印出来，常看记忆

```
你是一位知识框架提炼专家。请从下面内容中提取“迎合领导”的底层框架。
要求：
1. 框架层次：至少分到 3 级（层 / 子模块 / 要点）
2. 提取原则：
   - 只抓结构性信息：三层的结构是什么、每层包含哪些模块、模块之间的关系
   - 忽略：具体案例、比喻、论证细节、情绪化表达
3. 输出格式：
   - 用 Markdown 列表/标题层级呈现
   - 每个节点用短词组，不要长句
   - 在框架顶部，用 1 句话概括这个框架的核心逻辑
4. 约束：
   - 不要自己编内容里没出现的东西
   - 不确定的地方用“【待确认】”标出
   - 不要管多少个节点数量，尽可能的完备

```

### 3. 【微观-阅读细节层】Obsidian 内的交互增强

底层原则：多次反复，联想回忆

| 阅读动作     | 具体方法                                     | 涉及工具/快捷键                                       | 效果                                 |
| :----------- | :------------------------------------------- | :---------------------------------------------------- | :----------------------------------- |
| **抓重点**   | 标注每个段落的核心目的                       | 插件 `Modevol`                                        | 快速识别段落主旨，不迷失在细节中。   |
| **破难点**   | 对不懂的地方即时提问，增加脚注               | 插件 `Copilot` + `OpenRouter`<br>快捷键：`Ctrl+Alt+F` | 通过脚注增加理解深度，形成知识沉淀。 |
| **内化思考** | **灵魂三问**：我的目的是什么？我怎么用这个？ | 🧠 **大脑**                                            | 将知识转化为行动，拒绝死记硬背。     |

阅读过程，采用obsidian插件`copilot`,借助于OpenRouter免费的大模型：

- 借助obsidian modevol插件，渐构标注每一个段落的核心目的，帮助自己快速理解段落。

- 借助大模型，对不懂的地方及时提问，通过脚注`ctrl+alt+f`的方式增加理解深度。

- 借助自己的大脑，提问思考一下：我的目的是什么？我怎么用这个？跟我过去经验对比如何？

- - **脚注管理**：你提到的 ctrl+alt+f 脚注法非常棒。建议配合 Obsidian 的 **Hover Editor** 插件使用。这样你的鼠标悬停在脚注上时，可以直接弹出一个小窗口阅读 AI 给你的补充解释，而不用跳转到页面底部，保持阅读流的心流（Flow）不断。

- **反共识提问**：在使用 Copilot 时，除了让它解释不懂的地方，可以刻意让它做“红队”（Red Teaming）：

  > “作者在这个段落提出了 [某某观点]。请你扮演一个批判性思考者，帮我指出这个观点在现代商业环境/现实生活中**可能存在的局限性或反面案例**。”（这能极大地刺激你的独立思考）。

- 文件后添加QA提问和回答，辅助自己回忆刚才看了什么。（每个QA不超过100字）

- 思考如何实战，和AI讨论如何帮助到自己，最小MVP行动内容
