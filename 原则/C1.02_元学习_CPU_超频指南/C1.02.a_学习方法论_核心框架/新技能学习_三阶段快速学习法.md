传统学习方式：**先学理论 → 再做实践 → 希望能记住**

Dan Koe 的学习方式：**先规划项目 → 再学习所需内容 → 动手构建 → 遇到问题再查资料**

传统方式的弊端：

- 信息过载：看无数教程，填满大脑噪音与混乱
- 大部分信息被浪费：与实际项目脱节
- 导致焦虑和效率下降：感觉什么都没学到
- 学习速度慢：没有目标驱动，学习效果差

[[项目驱动学习]]的优势：

- 学习量与项目进展直接相关
- 真正有用的信息被自动筛选
- 多巴胺自然涌入大脑：大信号表明信息对项目完成至关重要
- 潜意识持续工作：即使在休息时也在处理问题

**这就是为什么有些人学两天就能上手新技能，而你学了半年还停留在理论阶段。**
# 新技能学习 SOP

## 核心理念

**快速学习**: 在最短时间内达到可用水平，而非追求完美掌握。

**80/20法则**: 20%的知识可以解决80%的问题。

**关键洞察**: 学习不是线性的，通过实践项目可以快速建立理解。

---

## 三阶段学习法

### 阶段1: 建立全景 (Day 1-2)

**目标**: 理解整体框架，知道"有哪些概念"和"它们是干什么的"

**方法**:
- ❌ 不要：直接看官方文档（太详细，容易迷失）
- ❌ 不要：直接写代码（没有全局观）
- ✅ 要做：看综述、教程、视频

**具体步骤**:
```markdown
## Day 1-2 任务清单
- [ ] 找一篇综述文章或入门教程
- [ ] 看3-5个YouTube视频（由浅入深）
- [ ] 画出知识图谱：
  - 核心概念有哪些？
  - 它们之间的关系？
  - 典型应用场景？
- [ ] 不写一行代码
```

**示例：学习PyTorch**:
```markdown
## PyTorch知识图谱
### 核心概念
- Tensor（张量）：数据结构
- Autograd（自动微分）：自动求导
- nn.Module（模块）：神经网络层
- Optimizer（优化器）：参数更新
- DataLoader（数据加载器）：批量数据

### 关系
Tensor → Autograd → nn.Module → Optimizer
```

**输出**: 一页纸的知识图谱

---

### 阶段2: 最小可行项目 (Day 3-7)

**目标**: 通过实践快速建立肌肉记忆

**方法**:
- ✅ 找一个Hello World教程
- ✅ 跑通官方Demo
- ✅ **魔改**: 修改参数/数据，观察结果变化

**具体步骤**:
```markdown
## Day 3-7 任务清单
- [ ] 找官方Quick Start教程
- [ ] 跑通第一个Demo（不求理解，先跑通）
- [ ] 魔改1：修改一个参数，看结果变化
- [ ] 魔改2：换一个数据集
- [ ] 魔改3：添加一个新功能
- [ ] 记录遇到的所有错误和解决方案
```

**示例：学习PyTorch**:
```markdown
## 最小可行项目：MNIST手写数字识别
### Day 3: 跑通官方教程
- [ ] 下载MNIST数据集
- [ ] 运行官方代码
- [ ] 成功训练模型

### Day 4-5: 魔改
- [ ] 魔改1：修改learning rate，观察收敛速度
- [ ] 魔改2：修改网络层数，观察准确率
- [ ] 魔改3：换成CIFAR-10数据集

### Day 6-7: 扩展
- [ ] 添加数据增强
- [ ] 添加学习率调度
- [ ] 可视化训练曲线
```

**关键**: 不要追求理解所有细节，先让它work

---

### 阶段3: 迁移应用 (Week 2-4)

**目标**: 将新技能应用到实际项目中

**方法**:
- ✅ 强行用新工具重写一个旧项目
- ✅ 遇到问题 → Google/StackOverflow → 记录笔记
- ✅ 建立个人知识库

**具体步骤**:
```markdown
## Week 2-4 任务清单
- [ ] 选择一个实际项目（最好是已有的项目）
- [ ] 用新技能重写/重构
- [ ] 遇到问题：
  - Google搜索
  - 查看官方文档
  - StackOverflow
  - 记录到笔记
- [ ] 建立个人代码库（常用代码片段）
```

**示例：学习PyTorch**:
```markdown
## 实际项目：图像分类
### Week 2: 基础实现
- [ ] 用PyTorch重写之前的TensorFlow项目
- [ ] 实现数据加载
- [ ] 实现模型训练
- [ ] 实现模型评估

### Week 3: 优化
- [ ] 添加混合精度训练
- [ ] 添加分布式训练
- [ ] 优化数据加载速度

### Week 4: 总结
- [ ] 整理常用代码片段
- [ ] 写一篇学习笔记
- [ ] 分享给团队
```

## 学习资源选择

### 优先级排序

**第一优先级**（快速入门）:
1. YouTube视频教程（视觉化，易理解）
2. 官方Quick Start（最权威）
3. 博客教程（实战经验）

**第二优先级**（深入理解）:
1. 官方文档（详细但枯燥）
2. 经典书籍（系统但慢）
3. 学术论文（理论但难）

**避免**:
- ❌ 过时的教程（检查发布日期）
- ❌ 过于复杂的教程（从简单开始）
- ❌ 没有代码的教程（理论太多）

## 常见陷阱

### 陷阱1: 教程地狱

**症状**: 看了10个教程，还是不会用

**原因**: 只看不练

**解决**: 
- 看1个教程 → 立即实践
- 不要追求"看完所有教程再开始"

### 陷阱2: 完美主义

**症状**: 想要完全理解每个细节才继续

**原因**: 害怕遗漏知识

**解决**:
- 接受"暂时不理解"
- 先让它work，再理解why
- 80%理解就够了

### 陷阱3: 没有实践项目

**症状**: 学完就忘

**原因**: 没有应用场景

**解决**:
- 立即找一个实际项目
- 强行用新技能
- 在实践中巩固

## 我的实践

**学习PyTorch**:
- Day 1-2: 看视频+画知识图谱
- Day 3-7: 跑通MNIST，魔改3次
- Week 2-4: 用PyTorch重写图像分类项目
- 总时间: 约30小时
- 结果: 可以独立完成项目

**学习Git**:
- Day 1: 看视频理解版本控制概念
- Day 2-3: 跑通基础命令（add, commit, push）
- Week 2: 在实际项目中使用
- 总时间: 约10小时
- 结果: 可以日常使用
