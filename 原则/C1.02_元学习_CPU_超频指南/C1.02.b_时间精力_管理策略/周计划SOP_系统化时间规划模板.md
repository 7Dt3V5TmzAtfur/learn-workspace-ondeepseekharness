# 周计划 SOP (GTD for Academia)

## 核心理念

**周复盘的目的**: 不是检查完成了多少任务，而是**确保你在做正确的事**。

**GTD核心**: Getting Things Done = 清空大脑 + 系统管理 + 定期回顾

**时间**: 每周日晚上，60-90分钟

## 完整流程

### 阶段0: 检查点 (Checklist) - 15分钟

**清空所有收件箱**:
- [ ] Email收件箱 → 归档/回复/转任务
- [ ] 微信/Slack未读消息 → 处理完毕
- [ ] 桌面文件 → 归档到对应文件夹
- [ ] 下载文件夹 → 清空或归档
- [ ] 浏览器标签页 → 关闭或加入阅读清单
- [ ] 手机通知 → 清零

**同步所有系统**:
- [ ] 查看日历下周安排
- [ ] 查看项目看板状态
- [ ] 查看待办清单

**目标**: Inbox Zero - 所有输入都被处理

---

### 阶段1: 复盘本周 - 20分钟

#### 1.1 成果回顾

**记录完成的事**:
```markdown
## 本周完成
### 科研产出
- [x] 完成实验X，结果符合预期
- [x] 写完论文Y的Method部分
- [x] 读完5篇相关论文

### 其他成就
- [x] 完成导师布置的任务
- [x] 参加组会并分享
```

**量化指标**:
- 深度工作时间：__ 小时（目标：20小时/周）
- 论文阅读：__ 篇（目标：5篇/周）
- 代码提交：__ 次
- 论文写作：__ 字

#### 1.2 障碍分析

**未完成的任务**:
```markdown
## 本周未完成
- [ ] 论文Z的Introduction（原因：被实验bug拖延）
- [ ] 学习新工具（原因：优先级不够高）
```

**障碍分类**:
| 障碍类型 | 示例 | 解决方案 |
|---------|------|---------|
| 时间估算错误 | 以为2小时能完成，实际需要8小时 | 下次×2估算 |
| 优先级错误 | 做了不重要的事 | 重新评估优先级 |
| 外部依赖 | 等待合作者反馈 | 提前催促或并行其他任务 |
| 技能不足 | 不会用某个工具 | 安排学习时间 |

#### 1.3 平衡检查

**5个方向的进展**:
```markdown
## 方向平衡度检查
- 主项目A：40% 时间 ✅ 符合预期
- 探索项目B：20% 时间 ✅ 符合预期
- 文献阅读：15% 时间 ⚠️ 偏低，需增加
- 技能学习：10% 时间 ✅ 符合预期
- 学术服务：15% 时间 ❌ 过高，需减少
```

**调整建议**:
- 减少学术服务（拒绝一些审稿请求）
- 增加文献阅读时间（每天早上1小时）

---

### 阶段2: 规划下周 - 25分钟

#### 2.1 确定本周三件事 (The Big 3)

**原则**: 如果只能完成3件事，哪3件最重要？

```markdown
## 下周三件事 (The Big 3)
1. 🎯 完成论文X的实验部分并写完Results
2. 🎯 提交会议Y的投稿
3. 🎯 完成导师要求的项目Z的原型
```

**检验标准**:
- 这3件事完成后，本周就算成功
- 其他事都是bonus

#### 2.2 更新项目看板

**看板状态**:
```
Backlog → Next Up → In Progress → Done
```

**操作**:
1. 将本周完成的任务移到Done
2. 将下周要做的任务从Backlog移到Next Up
3. 限制In Progress数量（最多3个）

#### 2.3 预约时间块

**在日历上锁死时间**:
```markdown
## 下周时间块
### 周一
- 09:00-12:00: 深度工作 - 写论文X的Results
- 14:00-17:00: 实验 - 跑最后一组对比实验

### 周二
- 09:00-12:00: 深度工作 - 准备会议Y的投稿材料
- 14:00-16:00: 会议 - 与导师讨论

### 周三
- 09:00-12:00: 深度工作 - 项目Z原型开发
- 15:00-17:00: 组会

### 周四
- 09:00-12:00: 深度工作 - 继续项目Z
- 14:00-17:00: 文献阅读

### 周五
- 09:00-11:00: 处理杂事和邮件
- 14:00-17:00: 周复盘准备
```

**原则**:
- 深度工作时间优先锁定（早上精力最好）
- 会议和杂事安排在下午
- 留出buffer时间应对突发事件

---

### 阶段3: 预防死角 - 10分钟

#### 3.1 检查等待中的任务

**等待清单**:
```markdown
## 等待中 (Waiting For)
- [ ] 等待合作者A反馈论文（已等待5天） → 本周催促
- [ ] 等待审稿人意见（预计下周） → 继续等待
- [ ] 等待服务器管理员分配算力（已等待3天） → 本周催促
```

**行动**:
- 超过3天未回复 → 发邮件催促
- 超过1周未回复 → 考虑替代方案

#### 3.2 检查长期项目

**长期项目健康度**:
```markdown
## 长期项目检查
- 项目A（博士主项目）：✅ 本周有进展
- 项目B（探索方向）：⚠️ 连续2周未推进 → 本周必须投入时间
- 技能学习（PyTorch）：❌ 连续3周未学习 → 重新评估是否继续
```

**规则**:
- 长期项目连续2周未推进 → 警告
- 连续4周未推进 → 考虑暂停或放弃

#### 3.3 检查承诺

**对外承诺清单**:
```markdown
## 本周承诺
- [ ] 周三前给导师发进度报告
- [ ] 周五前完成审稿任务
- [ ] 周日前回复合作者邮件
```

## 常见问题

### Q1: 周复盘总是拖延怎么办？

**原因**: 觉得是负担，没有即时反馈
**解决**:
- 固定时间（如周日晚上8点）
- 设置提醒
- 与朋友约定互相监督
- 记录复盘带来的好处（如避免了哪些坑）

### Q2: 复盘时发现本周一事无成怎么办？

**心态**: 这正是复盘的价值 - 及时发现问题
**行动**:
- 分析原因（是任务太多？还是被打断？）
- 调整下周计划（减少任务量或提高专注度）
- 不要自责，专注于改进

### Q3: 计划总是赶不上变化怎么办？

**现实**: 学术界充满不确定性
**策略**:
- 只锁定20-30%的时间（留出buffer）
- The Big 3要有弹性（如果A被阻塞，转向B）
- 每天早上微调当天计划

## 我的实践

**统计**:
- 坚持周复盘：52周（1年）
- 平均时长：75分钟
- 完成率提升：从60% → 85%

**收获**:
- 更少焦虑（知道自己在做什么）
- 更高效率（聚焦重要的事）
- 更好平衡（及时发现偏离）
